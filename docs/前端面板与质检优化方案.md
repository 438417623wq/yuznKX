# 零、勘察结论（方案的事实基础）

### 变量链路是断的，三个断点叠加

1. **MVU 四件套没有运行时消费。**
   `mvuSchemaText` / `mvuInitvarText` / `mvuUpdateRulesText` / `mvuVariablesJson` 全项目只出现在：
   喂给 AI 当上下文（`project_prompt_builder`）、本地质检比对（`text_quality_scanner`）、
   导出页展示（`project_export_extension`）。
   ⛔ **`worldbook_packager.dart` 里没有它们 —— MVU 三件套根本没进角色卡。**

2. **模型输出永远不触发变量写入。**
   变量宏只在 `_replaceMacros` 里执行，而它的 20+ 调用点全在**输入侧**
   （系统提示 / 世界书 / 作者注释 / 开场白 / stop 序列 / `sendMessage` 里的**用户**消息）。
   `_postProcessMessage` 不调用它 → 模型吐的 `{{setvar::...}}` 只会原样显示。
   *可验证：聊天输入框手打 `{{setvar::角色.好感度::50}}` 会生效，模型自己吐则不会。*

3. **`VariableManagementScreen` 全项目无任何 import —— 死页面。**
   用户无法查看 / 手动初始化会话变量，面板只能显示兜底 0。

### 可复用的先例

**记忆模块已经把「模型输出 → 解析 → 写库 → 从显示剥离」做对了**：
`_postProcessMessage` → `memoryProvider.processCommands(finalContent)`（`memory_provider.dart:762`），
解析 `<tableEdit>…</tableEdit>`，`allowWrites` 受「会话归属 + `isAiWriteTable` 开关」双重门控。
**变量模块缺的正是这条管道 —— 照搬即可，不要另起炉灶。**

### 其它已验证事实

- `frontend_stage_panel.dart` 的 `_generate()` **不传 `userHint`**，而后端
  `buildFrontend(userHint:)` 参数是有的 → AI 拿不到用户意图。
- `ProjectEntry.revision`（重写次数）**从未被写入过**。
- `TextQualityScanner` 全是字符串规则，读不懂设定语义；`CheckIssue.suggestion` 有内容但 UI 只能展示+跳转。

### 结论

前端面板已补上 MVU 六环节里的「⑥状态栏渲染」。现在缺 **①`[InitVar]` 初始化 + ③解析器/reducer + 应用**。
这与「导入的 MVU 卡变量不生效」是**同一个洞**，一套解析器同时解决。

# P1 变量管道（地基）

## P1.1 数据契约

### 角色卡上的变量定义（新增）

写进 `extensions.ykx_variables`，跟着卡走：

```json
{
  "version": 1,
  "init": { "角色.好感度": 30, "角色.生命值": 82, "关系.林昭.好感度": 62 },
  "rules": "变量更新规则（自然语言，喂给模型看）",
  "instruction": "追加给模型的更新指令（可空，空则由 rules 生成）"
}
```

- 工坊导出时由 `mvuVariablesJson` + `mvuInitvarText` + `mvuUpdateRulesText` 组装。
- **旧卡没有这个字段 → 变量功能整体不激活，行为与现在完全一致**（向后兼容的关键）。

### 变量存储保持平铺

现有 `chatVariablesProvider` 是 `Map<String, dynamic>`，键就是路径字符串（`角色.好感度`）。
**不改这个设计**：前端卡垫片 `readPath` 已按平铺 + 逐层下钻实现，改了要动两处。

新增工具 `VariablePath`：
- `toPointer('角色.好感度') → '/角色/好感度'`（解析 JSONPatch 用）
- `fromPointer('/角色/好感度') → '角色.好感度'`
- `readFlat(vars, path)`：先查平铺键，再按 `.` 下钻（与垫片 JS 行为对齐）

## P1.2 新增文件

```
lib/features/variables/
├── domain/
│   ├── models/variable_definition.dart   # 卡上的变量定义（init/rules/instruction）
│   ├── models/variable_update.dart       # VariableUpdate{op,path,value} + Batch
│   └── variable_path.dart                # 路径 ↔ JSONPointer + readFlat
└── data/
    ├── variable_runtime.dart             # 初始化 / 应用 / 生成指令（核心）
    ├── variable_command_parser.dart      # 解析模型输出里的更新指令块
    └── variable_extract_service.dart     # 兜底：额外发一次「提取变量变化」
```

## P1.3 解析器：主格式 + 宽松降级

**主格式**（对齐 MVU 约定，模型每轮在回复末尾输出）：

```
<UpdateVariable>
<Analysis>好感度因为主角帮了忙而上升</Analysis>
<JSONPatch>
[{"op":"replace","path":"/角色/好感度","value":35}]
</JSONPatch>
</UpdateVariable>
```

**宽松降级链**（任何一步成功就停）：
1. `<UpdateVariable>…</UpdateVariable>` 里的 `<JSONPatch>` 数组
2. 回复里任意位置的裸 JSON Patch 数组（`[{"op":...}]`）
3. `<变量更新>…</变量更新>` 中文标签
4. 变量宏 `{{setvar::key::value}}` / `{{addvar::key::delta}}`（复用现有 `_executeVariableAction` 语义）

**操作映射**：`replace`/`add` → `set`；`increment`/`add` 带数值 → `add`；`remove` → `delete`。

⛔ **解析失败必须静默降级**，不能因为模型吐了半截 JSON 就抛错或中断生成。
⛔ 解析成功后要把指令块**从显示内容里剥掉**（照搬记忆模块的 `replaceAll(RegExp(...), '')`）。

## P1.4 应用：幂等与去重

- `set` 天然幂等；`add` / `delete` **重放会出错**（数值翻倍、删已删的）。
- 方案：`VariableRuntime` 维护 `_appliedTurns: Set<String>`（键 = `sessionId + messageIndex + 内容哈希`），
  同一轮重复调用直接返回。
- 应用前写一份快照到 `metadata['variableSnapshot']`，供「撤销本轮」用（可选，P1 可先不做）。

## P1.5 接线点

| 位置 | 改动 |
|---|---|
| `chat_provider._postProcessMessage` | 在 `_applyRegex` 之后、记忆 `processCommands` 旁边加一行：`_ref.read(variableRuntimeProvider).processCommands(finalContent, sessionId: sessionId, allowWrites: isSameSession && 变量开关)` |
| `chat_provider._assemblePromptMessages` | 把变量更新指令追加到作者注释槽位之后（**独立槽位**，不污染 `authorsNote`）。用 `RpHubContextDepthInjection` 加一条 |
| `CharacterExporter` / `_parseV2Spec` | `ykx_variables` 随 `extensions` 自动往返，无需额外代码（`rawExtensions` 已原样保留） |
| 会话首次进入 | 变量为空 + 卡上有 `init` → 写入初始值。**只在为空时执行**，否则会覆盖用户/AI 改过的值 |
| `variable_management_screen.dart` | 接进 `app_drawer` + 设置页；加「从卡初始化」「清空」「导入/导出 JSON」 |

## P1.6 兜底提取（用户选的「两者都要」）

- 触发条件：本轮**没解析到指令块** 且 卡上有变量定义 且 开关开启。
- 请求：把「本轮 AI 回复 + 当前变量快照 + 变量规则」发给模型 → 只输出 JSON Patch。
- 用 `_tempExtract`（0.3，与材料拆解同一档）。
- ⛔ 必须**异步、不阻塞**消息落库；失败只记日志，不弹错误（否则每轮都可能骚扰用户）。
- UI 上给一个开关：「变量更新：指令块 / 指令块+提取 / 关闭」。

## P1.7 工坊侧

- `card_project_service`：`generateMvu` 的提示词改成**输出运行时格式**（现在的 `updateRules` 是自然语言 YAML，
  模型照着它无法产出可解析的 patch）→ 改成「输出 init 变量表 + 一段给模型的更新指令」。
- `frontend_card_packager` 或新增 `variable_packager`：把 MVU 四件套组装成 `extensions.ykx_variables`。
- `worldbook_packager.buildCharacter`：补上 `ykx_variables`（**这是当前最大的漏洞 —— 三件套根本没进卡**）。

## P1.8 风险

| 风险 | 处置 |
|---|---|
| token 成本：指令块每轮约 100~300 token | 提供「指令块 / +提取 / 关闭」三档开关 |
| 弱模型学不会格式 | 用户已选「两者都要」，兜底提取是关键 |
| `add` 重放翻倍 | turnId 去重（P1.4） |
| 导入的 MVU 卡格式不确定 | 解析器做宽松降级；**建议提供一张真实 MVU 卡做验证样本** |

# P2 面板定制

## P2.1 需求输入（修掉「AI 不知道我想要什么」）

- `FrontendStagePanel` 加「面板需求」多行输入框，`_generate()` 把它作为 `userHint` 传下去。
- 快捷 chip 一键填模板化需求：「状态条」「属性表」「关系网」「资源+时间」「战斗面板」。
- 生成前把**卡上真实的变量定义**（`ykx_variables.init` 的键）一并喂给 AI，而不是只给 `designSpec`。

## P2.2 对话式迭代

- 新增 `WorkshopActions.refineFrontend(projectId, instruction)` →
  `CardProjectService.refineFrontend` → `ProjectPromptBuilder.buildFrontendRefine`。
- Prompt 结构：`当前 HTML` + `用户的新要求` + `变量清单` → 要求输出**完整替换后的 HTML**
  （⛔ 不要让模型输出 diff —— 它对 diff 的准确率远低于重写）。
- **不直接覆盖**：结果先进「待确认」状态，给「预览 / 应用 / 放弃」三个动作。
- 版本历史：`FrontendStagePanel` 本地保留最近 5 版 HTML（+ 应用时间），可一键回退。
  不落库 —— 面板本身已在项目里，历史只是操作缓冲。

## P2.3 编辑体验

- 语法高亮：项目已有 `flutter_highlighter`，直接复用。
- **「插入变量」面板**：列出卡上所有变量路径，点一下在光标处插入 `YKX.getVariable('角色.好感度')`。
  手机上这比手打路径实用得多。
- 全屏编辑页（手机上编辑 HTML 的必要条件）。
- 实时预览已有（500ms 防抖），保留。

## P2.4 模板参数化

现在模板把字段名/上限/颜色写死在 HTML 里。改成：
- `FrontendTemplate` 带一份 `List<TemplateField>{ path, label, max, color, control }`
- 选模板后进入「字段编辑」：可改字段名、上限、颜色、控件类型（进度条/数值/标签）
- 改完 → 由模板的 HTML 骨架 + 字段表**生成** HTML（模板变成生成器而非固定产物）
- 用户仍可直接编辑生成的 HTML（生成后就是普通 HTML，不再回写模板）

# P3 质检 AI 化 + 逐条修复

## P3.1 两段式质检

| 阶段 | 成本 | 产出 |
|---|---|---|
| 本地规则（现有） | 0 token，秒出 | 结构完整性 / AI 味 / 重复短语 / 关键词缺失 |
| **AI 复核（新增）** | 约 2~4k token，一次性 | 设定一致性 / 人设走形 / 前后矛盾 / 变量与设定冲突 / 开场白脱节 |

- `CheckIssue` 加 `source: CheckSource{local, ai}`，UI 上分组显示（本地问题在前，AI 问题在后）。
- AI 复核的输入：`designSpec` + 全部 `characterCard` 条目 + 全部 `worldbook` 条目 +
  前端面板 HTML + 变量表 + **本地已发现的问题清单**（避免重复报）。
- ⛔ 要求模型**只报确定的问题**，并给 `severity`；宁缺毋滥（本地质检的「宁可漏报不要误报」原则同样适用）。

## P3.2 逐条修复

- `CheckIssue` 增加 `repairable: bool`（AI 问题默认可修；本地问题里结构类可修、文本类只建议）。
- UI：每条可修问题旁加「修这条」按钮 → `WorkshopActions.repairIssue(projectId, issueId)`。
- Prompt 按问题类型分流：
  - `characterCard` / `worldbook` 条目 → 输入「当前内容 + 问题 + 修复要求」→ 输出**完整新内容**
  - `frontend` → 输入「当前 HTML + 问题」→ 输出新 HTML
  - 结构类（缺关键词等）→ **不走 AI**，直接给出可点选的修补（比如「补一个关键词」）
- **diff 预览**：应用前展示前后对比。行级 diff 本地算（LCS），不引第三方包。
- 应用 → `setEntryContent` + `revision + 1`（**终于用上这个字段**）。
- 应用后**自动重跑本地质检**（0 token），问题消失则从列表移除，形成收敛反馈。

## P3.3 批量

- 「修复所有可修问题」：串行执行，每条都出 diff。
- 提供「本次全部应用」以跳过逐条点击，但 diff 仍逐条可见。

## P3.4 成本控制

- AI 复核默认**手动触发**（点按钮），不自动跑。
- 全部走现有 `WorkshopException` / `beginBusy` / 流式预览机制，不新增状态通道。

## P2.4 为什么没做

模板参数化要把 3 个内置模板从「固定产物」改造成「HTML 骨架 + 字段表 → 生成器」，
是一次结构改造，且与已落地的「需求输入 + 对话式迭代」**功能重叠**：
用户现在可以直接说「把血条改成蓝色、加一个金钱字段」，AI 会重写整块面板。

考虑到它风险高于收益（会动已验证的模板代码），本轮跳过。
如果确实需要「不用 AI 也能改字段名/上限/颜色」，可以单独提。

## 三处按推荐值假设（无真实 MVU 样本）

1. **变量指令独立深度注入**（`depth: 1`，不占 Author's Note 槽位）
2. **AI 质检手动触发**（不自动跑，省 token）
3. **解析器写宽松降级链**（四级，任何一步命中即停）

若手上有一张真实的 MVU 卡，建议导入验证一遍 —— 解析器的格式假设需要实测校准。

`NavigatorState.pop()` 完全不查它，`if (didPop) return;` 就是官方标准写法。无需真机实测。

# 八、补单元测试（2026-09-19 20:2x）

P1 里风险最高的部分是解析器的**格式假设** —— 四级降级链、字段名宽容、`add` 退化、
裸 JSON 不误剥离，全部是按 MVU 约定猜的（手上没有真实 MVU 卡样本）。
所以补了 `test/variable_pipeline_test.dart`（约 60 个 test）把这些约定钉死。

| 覆盖对象 | 钉住的约定 |
|---|---|
| `VariablePath` | 规范化只去首尾、Pointer 的 `~0`/`~1` 往返、**平铺键优先于嵌套**、`toNumber` 兜底 |
| `VariableOp.fromJsonPatch` | 字段名宽容、op 映射、`add` 值非数字退化 set、缺 path/value 返回 null |
| `VariableOp.fromTextLine` | `: = ：` 都认、`+5` 是累加而 `-5` 是「设为负数」 |
